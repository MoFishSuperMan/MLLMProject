\chapter{总结、反思与展望}

\section{开题目标完成情况}

本文围绕开题报告中提出的多模态文档智能助手目标，完成了一个从后端模型 pipeline 到前端交互界面的系统原型。系统能够上传 PDF 或图片，解析页面，构建文本和视觉 evidence，使用 Text-RAG 或 MM-RAG 进行问答，并在前端展示连续 PDF 预览与 evidence 高亮。实验表明，多模态 evidence 对文档问答具有明显价值：在 40 个 DocVQA/ChartQA 样本上，MM-RAG 总体 EM 达到 0.9750，显著超过 Text-RAG 的 0.3750。

对照开题报告，最终完成情况可以概括为四点。第一，\textbf{多模态 RAG 架构}已经落地：系统完成 PDF/图片解析、text/table/figure/code 等结构化 chunk 构建、页面图、局部 crop、向量检索、重排和生成式回答。第二，\textbf{视觉定位与溯源}已经落地：每个 evidence 保留页码、chunk 和 bbox，前端可以在 PDF 预览中高亮对应区域。第三，\textbf{评测与报告}已经完成：项目对比了 Text-RAG 与 MM-RAG，并给出了定量结果、案例和错误分析。第四，\textbf{路由决策}完成了工程化落地：原计划中的强化学习路由没有进行真实训练，但系统实现了 GRPO-style auto router、候选 VLM 打分、retrieval modes 选择和策略更新钩子。

\section{项目调整与反思}

相比开题阶段的设想，最终项目主要有三处调整。第一，视频片段理解没有作为期末主要评测对象，项目将重点收敛到 PDF 与图片文档，这与课程题目中的文档问答场景更直接对应。第二，多模态向量化没有训练大型跨模态检索模型，而是实现统一文本-图像 embedding 接口、轻量图像特征和可选 Native ViT 图像编码器，使系统更容易在单机环境下稳定运行。第三，多模型自动选择没有训练真实 Qwen-0.5B 路由器，而是通过 GRPO-style auto router 暴露可训练接口，并在演示阶段用确定性特征、候选奖励和策略钩子完成自动路径选择。虽然这些调整降低了训练复杂度，但提高了项目完成度、可复现性和演示稳定性。

\section{系统局限}

当前系统仍存在以下局限：

\begin{itemize}
  \item \textbf{复杂表格结构理解仍有限}：系统已经支持表格区域抽取和 Markdown 入库，但对跨列、跨行、合并单元格和复杂日程表的行列语义恢复仍不稳定。
  \item \textbf{OCR 噪声影响检索}：当 OCR 漏字、错字或顺序混乱时，文本 chunk 和区域 anchor 都会受影响。视觉模型可以弥补部分问题，但如果 crop 本身错误，仍会生成错误答案。
  \item \textbf{视觉区域检测仍偏规则化}：当前 region 生成主要针对实验样本中常见问题类型，泛化到任意文档时可能需要更强的 layout detector、表格检测器或端到端视觉检索模型。
  \item \textbf{模型调用成本和延迟}：Qwen3-VL 对整页视觉摘要的处理仍较慢。在线问答必须控制输入图片数量和分辨率，否则会显著增加延迟与显存压力。
  \item \textbf{评测规模有限}：当前 20+20 样本可以验证主要功能和改进方向，但不足以代表全部文档类型。未来需要更大规模、更细粒度的评测集合。
\end{itemize}

\section{AGI 视角下的潜力与瓶颈}

从 AGI 视角看，文档智能助手是多模态大模型落地的重要场景。真实办公和科研环境中的知识并不只存在于纯文本中，而是混合在 PDF、图表、表格、扫描件、网页截图和演示文稿中。一个更接近通用智能的系统，需要像人一样阅读页面：先观察版面结构，再定位证据区域，理解文本与图表之间的关系，最后给出带来源的结论。本文系统在小规模上验证了这一方向的可行性。

但当前系统距离真正的 AGI 文档助手仍有明显距离。首先，模型仍然依赖外部规则帮助其选择区域，还不能自主形成稳定的阅读策略。其次，模型对复杂表格和跨页推理的鲁棒性不足，缺乏长期记忆和全局任务规划。再次，生成模型虽然能给出流畅解释，但仍可能在证据不足时过度推断。因此，未来的文档智能系统不仅需要更强 VLM，也需要更可靠的工具调用、结构化解析、检索验证和自我纠错机制。

\section{未来工作}

后续可以从以下方向改进：

\begin{enumerate}
  \item \textbf{结构化表格解析}：引入表格检测和行列重建，将 OCR box 合并为结构化 Markdown 或 DataFrame，提升日程表、财报表格和复杂表格问答能力。
  \item \textbf{视觉检索模型}：尝试 ColPali 类原生视觉检索方法，减少对 OCR 文本的依赖，并提升复杂版面召回质量。
  \item \textbf{学习式路由}：在规则路由稳定后，收集更多查询和答案反馈，用轻量模型学习 query 到 route、crop 类型和 evidence 类型的映射。
  \item \textbf{更大规模评测}：扩展到更多 DocVQA、ChartQA、TextVQA 和自建中文文档样本，报告不同文档类型下的细分性能。
  \item \textbf{前端产品化}：继续优化 PDF viewer、chunk 管理、多文件会话、证据编辑和失败重试，使其更接近真实知识库产品。
\end{enumerate}

\section{结论}

本文完成了一个多模态文档理解问答系统，并通过定量实验验证了多模态 RAG 相比纯文本 RAG 的优势。系统在工程上实现了文档上传、解析、索引、检索、生成、引用和 PDF 高亮预览，在实验上达到了较高的 DocVQA/ChartQA 子集准确率，在分析上明确了复杂表格定位和长文档视觉成本等后续挑战。整体来看，本项目满足课程期末验收对系统实现、定量实验、错误分析和反思展望的要求，也为后续构建更通用、更可靠的文档智能助手提供了基础。
