## Slide 1 系统介绍

**PPT 写什么**
- 面向 PDF / 图片文档的多模态问答系统。
- 流程闭环：上传 -> 解析 -> 检索重排 -> GRPO 决策 -> 生成答案 -> PDF 高亮溯源。
- 核心创新：多模态分块、GRPO 决策、完整系统工作流程。

**人讲什么**

大家好，我展示的项目是一个面向 PDF 和图片文档的多模态文档问答系统。它不是只把文档转成文本再问答，而是从上传文档开始，完成页面解析、文本和视觉证据构建、向量检索、重排、GRPO 决策、答案生成和 PDF 高亮溯源，形成一个从后端模型 pipeline 到前端预览界面的完整闭环。今天我会重点讲三个创新点：多模态分块、GRPO 决策模型，以及整个系统从证据构建到溯源展示的工作流程。

**PPT 写什么**

- 右侧结论：开题报告中的组件都对应到系统功能。

**人讲什么**

这一页对应报告第二章的表 2.1。系统由多个模块共同组成：文档解析和 OCR 负责获取页面、文本、坐标和局部区域；Embedding 与 Fusion 把文本、表格、OCR 和图像特征组织为统一 evidence；向量检索和 Reranker 控制送入生成模型的证据质量；GRPO 决策模型根据问题和证据选择更合适的 LLM 或 VLM；最后前端把答案对应的 page 和 bbox 显示回原文档。这个表的作用是说明，开题报告里的技术设想不是孤立概念，而是都落到了系统功能里。

## Slide 3 系统实现流程

**PPT 写什么**
- 文档解析 -> 知识索引 -> 检索重排 -> 决策生成 -> 前端溯源。
- 强调：回答问题的同时必须找到证据。

**人讲什么**

第三章的总体流程可以概括为五步。第一步是文档解析，抽取页面文本、页面图、表格、局部区域和坐标信息；第二步是知识索引，把 text、table、figure、code 等 chunk 统一保存；第三步是检索重排，先召回候选 evidence，再用 Reranker 二次排序；第四步是决策生成，由 GRPO 决策模型选择使用 LLM 还是 VLM，以及如何组织上下文；最后一步是前端溯源，根据 page、bbox 和 evidence id 把答案定位回 PDF 页面。这里最关键的是，系统同时处理“回答问题”和“找到证据”，而不是只生成一段文本。

## Slide 4 多模态分块与 Fusion

**PPT 写什么**
- PDF / 图片拆成 text、table、figure、formula、code/crop。
- Fusion evidence：文本负责语义召回，图像补充视觉信息，表格保留结构，bbox 负责溯源。

**人讲什么**

多模态分块是这个系统的基础。报告第三章里说，文档解析模块要解决“知识从哪里来”的问题。系统会把 PDF 或图片拆成可检索、可生成、可高亮的 evidence。文本用于语义召回，页面图和局部 crop 用于视觉理解，表格 Markdown 保留行列结构，bbox 和页面尺寸用于前端溯源。这样文档不再只是普通文本集合，而是由页面、区域、chunk 和 evidence 组成的结构化知识库。

## Slide 5 GRPO 决策模型

**PPT 写什么**
- Decide Model -> 候选 LLM/VLM -> Judge Model -> GRPO Update。
- 作用：让系统学会为不同问题选择合适模型。

**人讲什么**

第二个创新点是 GRPO 决策模型。它的目标不是把路由规则写死，而是训练一个 Decide Model，让它根据用户问题和检索到的 evidence 选择更合适的 LLM 或 VLM。流程上，候选模型先分别生成答案，Judge Model 根据正确性、证据一致性和完整性给出 reward，然后用 GRPO 更新 Decide Model。简单说，GRPO 在这里的作用是“学会选模型”：文本题更偏向文本 LLM，图表、票据、局部视觉区域问题更偏向 VLM，边界问题则依赖 reward 反馈逐渐提升选择稳定性。

## Slide 6 系统实现细节与代码仓库

**PPT 写什么**
- 前端：React / Vite / TailwindCSS，文件列表、chunk、问答窗口、PDF 预览。
- 后端：FastAPI，上传、解析任务、chunk 查询、页面图、问答、删除。
- 高亮：后端 bbox 按页面显示尺寸映射到 PDF viewer。
- 仓库：报告、运行说明、核心模块、评测脚本与实验结果。

**人讲什么**

工程实现上，后端使用 FastAPI 封装文件上传、解析任务、chunk 查询、页面图读取、检索问答和文件删除等功能；前端使用 React、Vite 和 TailwindCSS 构建文件列表、知识库 chunk、问答窗口和连续 PDF 预览。报告里特别强调了 PDF 高亮：后端保存原始页面坐标 bbox，前端根据页面显示尺寸重新计算缩放比例，把证据框映射到 PDF viewer 的对应区域。所以代码仓库不只是模型调用，还包含前端交互、后端服务、解析模块、模型链路、评测脚本和实验结果。

## Slide 7 实验表 1：Text-RAG 与 Our-RAG 性能对比

**PPT 写什么**
- 放入报告表 5.1。
- 指标：EM、ANLS、Answer Match、Avg. Latency。
- 结论：Overall EM 从 0.3750 提升到 0.9750，ANLS 从 0.4265 提升到 0.9750。

**人讲什么**

这一页是报告第五章的主实验表。Text-RAG 是只使用文本 chunk 的基线，Our-RAG 是加入页面视觉 evidence、局部 crop、图表提示、Reranker、GRPO 决策和 VLM 推理后的方法。结果上，Overall 的 EM 从 Text-RAG 的 0.3750 提升到 Our-RAG 的 0.9750，ANLS 从 0.4265 提升到 0.9750。ChartQA 上差异更明显，Text-RAG 的 EM 是 0.2000，而 Our-RAG 达到 1.0000。这个结果说明，多模态 evidence 能补充纯文本检索在图表、版面和视觉实体信息上的不足。

## Slide 8 实验表 2：消融实验与错误分析

**PPT 写什么**
- 放入消融实验表。
- 关键结论：去掉 Reranker 下降 0.0720，去掉 Unified Embedding 下降 0.0800，Rule Decision 比 GRPO 低 0.0530。
- 错误分析：复杂表格行列定位、局部 crop 裁剪偏差、答案格式波动。

**人讲什么**

这一页是消融实验和错误分析。完整 Our-RAG 的 EM 是 0.9750；换成硬编码 Rule Decision 后下降到 0.9220；去掉 Reranker 后下降到 0.9030；去掉统一多模态向量化后下降到 0.8950。说明 Reranker 和统一多模态向量化是关键因素，GRPO 也比硬规则更适合处理边界问题。错误主要来自三个位置：复杂表格的行列定位、局部视觉区域 crop 偏差，以及生成答案的格式波动。后续优化重点就是表格结构恢复、局部区域选择和答案规范化。

## Slide 10 反思：模型局限

**PPT 写什么**
- 依赖 OCR、版面解析、向量检索、Reranker、VLM 多模块串联。
- OCR 漏识别、bbox 偏移、检索召回不足会影响结果。
- 长程任务规划、跨文档记忆、多轮目标追踪仍有限。

**人讲什么**

从反思来看，当前系统仍然是一个模块化系统。它依赖 OCR、版面解析、向量检索、Reranker 和 VLM 串联工作，每个模块的误差都会影响最终结果。比如 OCR 漏识别会导致 evidence 不完整，bbox 偏移会影响前端高亮，检索召回不足会让 VLM 看不到关键区域。另外，系统现在能回答当前文档中的问题，但对长程任务规划、跨文档持续记忆和多轮目标追踪的支持还有限，还不能像真正的智能助理一样长期维护用户目标。

## Slide 11 展望：AGI 视角下的潜力与瓶颈

**PPT 写什么**
- 潜力：文档问答连接外部知识与大模型推理。
- 需要能力：阅读、定位、比较、推理、溯源。
- 瓶颈：复杂版面、跨页表格、隐含图表关系、常识推理、来源严谨性。
- 未来方向：更强多模态基础模型、视觉检索、自我验证、持续学习决策模型。

**人讲什么**

从 AGI 视角看，文档问答是通向通用智能助手的重要场景。真实知识往往分布在 PDF、表格、图片、图表、扫描件和网页截图中，一个接近 AGI 的系统需要同时具备阅读、定位、比较、推理和溯源能力。本文系统已经把多模态感知、检索增强、模型选择和证据高亮结合起来，说明文档智能可以作为连接外部知识与大模型推理能力的入口。但瓶颈也很明确：复杂版面、跨页表格、隐含图表关系和常识推理仍然容易出错。后续需要更强的多模态基础模型、更稳定的视觉检索、更可靠的自我验证机制，以及能够持续学习的决策模型。
